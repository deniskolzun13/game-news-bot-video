# Бот новостей об играх для Telegram

Парсит новости с русскоязычных игровых сайтов (StopGame, Igromania, DTF), переписывает их
локальной LLM (Ollama) и публикует в Telegram-канал.

## Как это работает

```
RSS-ленты → парсеры → страница статьи (текст + фото) → Ollama → подбор фото
→ очередь свежих постов → Telegram-канал → SQLite (дедуп)
```

- **Источники** (проверено на август 2026):
  - StopGame — RSS `https://rss.stopgame.ru/rss_news.xml`
  - Igromania — RSS `https://www.igromania.ru/rss/news.xml`
  - DTF — RSS `https://dtf.ru/rss/all`, фильтр по игровым разделам (`/games/`, `/gameindustry/`, `/gamedev/`)
  - 3DNews — RSS игрового раздела `https://3dnews.ru/games/rss/`
  - VGTimes — RSS `https://vgtimes.ru/rss.xml`, фильтр по разделам `gaming-news` и `articles` (текст статьи подгружается скриптами, поэтому берётся описание из RSS)
- **Текст статьи** достаётся со страницы (селекторы в `article.py`); если страница
  недоступна — берётся описание из RSS.
- **Фото**: используются только чистые, высокого качества (мин. 1024px,
  отбрасываются размытые плейсхолдеры <30 КБ) — фон/баннер страницы игры в Steam
  (с CDN `cdn.akamai.steamstatic.com`, API без ключа) → обложка с Playground.ru
  (без ключа, проверяется совпадение названия) → Pixabay (оригинал, нужен ключ)
  → Википедия → официальная обложка SteamGridDB (нужен ключ). Картинки из самих
  статей не используются, поскольку на них бывают логотипы и водяные знаки.
  Если чистого изображения нет, пост выходит без фото. Перед публикацией фото
  ужимается до 1280px/JPEG (лимит Telegram).
- **Название игры определяет LLM** (с фолбэком на эвристику) — от него зависят
  поиск фото и хэштег. Поиск в Steam проверяет соответствие названия, чтобы
  не брать фото другой игры.
- **LLM**: Ollama `http://localhost:11434`, по умолчанию `llama3.1:8b`, запасная —
  `mistral`. Бот сам проверяет, запущен ли `ollama serve` и скачана ли модель,
  и выводит понятное сообщение об ошибке. Каждый пост проходит **вычитку**:
  отдельный прогон LLM исправляет орфографию и грамматику, не трогая
  содержание и хэштеги.
- **Дедупликация**: SQLite-файл `data/published.db`, новости с уже опубликованным URL
  пропускаются. Одинаковые новости с разных сайтов (например, с DTF и Igromania)
  распознаются через LLM по названию игры — публикуется только одна.
- **Без ссылок**: в посте нет ссылок на источник и кликабельных названий игр — только
  пересказ новости и хэштег. Перед хэштегом добавляется упоминание канала
  (@имя из `CHANNEL_ID`) — «ссылка» на канал для подписки.
- **Видео**: если в статье есть mp4/webm (og:video, до `MAX_VIDEO_SIZE_MB`=50 МБ) —
  пост публикуется с видео вместо фото. Если видео встроить не удалось
  (например, только YouTube-вставка, а YouTube недоступен) — новость пока
  пропускается: без встроенного видео пост не публикуется. Ссылки на видео
  в текст поста не добавляются.
- **Расписание**: посты планируются каждый час с 8:00 до 21:30 МСК; в каждом
  часу есть слоты `:00` и `:30`, поэтому при наличии новостей может выйти до
  двух постов в час.
- **Утверждение постов**: перед публикацией каждый пост приходит владельцу
  в личку с кнопками «Опубликовать» / «Пропустить» (выключается
  `APPROVE_POSTS=false`). Ручные публикации (`--now`, кнопка «Опубликовать
  сейчас») утверждения не требуют.
- **Панель управления кнопками**: любое сообщение владельцу открывает плитки —
  «Опубликовать сейчас», «Свой пост», «Очередь», «Последний пост»,
  «Удалить последний», «Статистика», «Здоровье», «Помощь». Команды
  `/publish_now`, `/stats`, `/next`, `/health`, `/help` тоже работают.
- **Галерея**: если в статье несколько крупных картинок — пост уходит
  альбомом из 2–3 фото (первое — чистое фото игры, если нашлось).
- **Форматирование**: заголовок поста выделяется жирным (HTML с
  экранированием, чтобы LLM-текст не сломал разметку).
- **Не повторять одну игру**: одна и та же игра не появляется в канале чаще
  раза в `GAME_REPEAT_HOURS` часов (по упоминаниям в заголовках).
- **Уведомления об ошибках**: сбои источников, застрявшие посты и ошибки цикла
  приходят владельцу в личку (не чаще раза в 10 минут по категории).
- **Бэкап БД**: при каждом старте копия `published.db` кладётся в
  `data/backups/` (хранятся 7 последних).
- **Команды в личке**: заранее укажите `OWNER_CHAT_ID` в `.env`. Если ID пока
  неизвестен, задайте секретный `OWNER_SETUP_CODE` и первым сообщением отправьте
  боту `/start <код>`; случайный пользователь не сможет забрать права владельца.
  Команды: `/publish_now`, `/stats`, `/next`, `/health`, `/help`.
- **Тихие часы**: с `QUIET_START_HOUR` (по умолчанию 22:00) до `QUIET_END_HOUR`
  (8:00) по `TIMEZONE` (Europe/Moscow) посты автоматически не публикуются —
  просроченные переносятся на утро с разбросом по минутам, чтобы не выходили
  пачкой. Ручные команды `--now` и `/publish_now` тихие часы игнорируют.
- **Свежесть и очередь**: в RSS берутся новости не старше `MAX_ITEM_AGE_HOURS`,
  а пост старше `NEWS_FRESHNESS_HOURS` при публикации удаляется. Очередь
  ограничена `QUEUE_CAPACITY` и переживает перезапуск бота.
- **Лимит caption**: если текст длиннее 1024 символов, фото и текст уходят
  отдельными сообщениями.
- **Ошибки источников изолированы**: падение одного сайта не останавливает бот.

## Структура проекта

```
├── bot.py            # точка входа: цикл по расписанию (+ --once, --now, --dry-run)
├── commands.py       # панель кнопок-плиток и команды в личке владельцу
├── config.py         # чтение .env и настроек
├── logging_setup.py  # лог в файл logs/bot.log + консоль
├── storage.py        # SQLite: опубликованные URL + очередь постов (+ статусы утверждения)
├── pipeline.py       # обработка новости: парс → LLM → фото → публикация/утверждение
├── article.py        # текст и фото со страницы статьи (селекторы по сайтам)
├── images.py         # цепочка подбора фото + ужатие под Telegram
├── llm_ollama.py     # Ollama: проверка serve/модели, пересказ, вычитка, название игры
├── publisher.py      # публикация в Telegram (aiogram): фото/галерея/видео
├── notifier.py       # уведомления об ошибках + отправка постов на утверждение
├── owner.py          # chat_id владельца (OWNER_CHAT_ID или файл)
├── parsers/
│   ├── rss_base.py   # общий RSS-парсер (feedparser)
│   ├── stopgame.py   # StopGame
│   ├── igromania.py  # Igromania
│   ├── dtf.py        # DTF (фильтр игровых разделов)
│   ├── threednews.py # 3DNews (игровой раздел)
│   ├── vgtimes.py    # VGTimes (фильтр gaming-news/articles)
│   └── __init__.py   # реестр источников
├── .env.example
└── requirements.txt
```

## Установка и настройка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env     # затем заполнить .env (см. чек-лист ниже)
.venv/bin/python bot.py --dry-run   # проверить сбор без публикации
.venv/bin/python bot.py             # запустить
```

## Запуск как systemd-сервис (используется здесь)

Бот живёт под systemd и сам перезапускается при падении, стартует при
загрузке системы:

```bash
cp gamenews-bot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now gamenews-bot
loginctl enable-linger $USER   # запуск при загрузке без входа в систему
```

Логи: `journalctl --user -u gamenews-bot -f`, плюс файл `logs/bot.log`.

## Расписание: внутри скрипта или cron?

В скрипте реализован планировщик: бот проверяет очередь публикации каждые
30 секунд (посты уходят с рандомной задержкой 1–3 часа) и раз в
`POLL_INTERVAL_MINUTES` минут собирает новые новости (`bot.py`).

**Внутри скрипта (используется здесь)** — бот постоянно работает, сам будит себя
по таймеру. Плюсы: ничего не нужно настраивать в системе, удобно для запуска
в Docker/systemd. Минусы: должен жить как процесс (если упадёт — надо
перезапускать, например через systemd `Restart=always`).

**Системный cron** — процесс не нужен, ОС запускает бота каждые N минут,
`--once` делает один прогон и завершается. В нём новые посты публикуются без
ручного утверждения, поскольку процесс не остаётся запущенным для обработки
кнопок Telegram:
```
*/30 * * * * cd /путь/к/проекту && .venv/bin/python bot.py --once
```
Плюсы: переживает сбои и перезагрузки, ничего не занимает в памяти между
прогонами. Минусы: нет точного расписания "каждые 30 минут от старта",
запуск по системным часам; нужно следить, чтобы прошлый прогон не
пересекался с новым (обычно не проблема при таком интервале).

## Чек-лист запуска

1. **Установить Python 3.10+** — `python3 --version`.
2. **Установить Ollama** — https://ollama.com (Linux: `curl -fsSL https://ollama.com/install.sh | sh`).
3. **Скачать модель**: `ollama pull llama3.1:8b` (или `ollama pull mistral`, если нет места).
4. **Проверить, что сервер запущен**: `curl http://localhost:11434/api/tags` должен вернуть JSON.
5. **Получить токен бота** у @BotFather: `/newbot` → имя → токен вида `123456:ABC-DEF...`.
6. **Создать канал** (или использовать существующий) и добавить бота **администратором**.
7. **Узнать id канала**: публичное имя `@channelname`, либо числовой `-100...`
   (узнать можно через @userinfobot или в Bot API `getUpdates`).
8. **Заполнить `.env`** (скопировать из `.env.example`):
   `TELEGRAM_BOT_TOKEN=...`, `TELEGRAM_CHANNEL_ID=@имя_канала`.
9. **Установить зависимости**: `pip install -r requirements.txt`.
10. **Проверить без публикации**: `python bot.py --dry-run` — в консоль и
    `logs/bot.log` уйдёт, что бот нашёл и что бы опубликовал.
11. **Запустить**: `python bot.py` (или через cron/`--once`, или systemd).
